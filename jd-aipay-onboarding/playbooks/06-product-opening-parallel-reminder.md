# 产品开通并行提醒

## 触发时机

- 服务端代码集成完成后、沙箱联调开始前。
- 沙箱联调完成后，如果商户尚未产品开通，必须再次主动提醒。
- 实名认证、证书准备等平台侧事项完成后，也要根据当前状态主动引导商户回到产品开通。

## 是否阻塞

不阻塞沙箱联调，但阻塞生产密钥、生产配置替换和线上验证。

产品开通与技术集成可以并行推进：产品开通前，可先完成技术集成、沙箱联调、实名认证和获取证书；产品开通完成并签约后，再生成密钥、替换正式配置并做上线验证。

## 推荐下一步判断

1. **未实名认证**：先引导商户完成实名认证，再回到产品开通页提交申请。详见 `playbooks/13-real-name-auth-guide.md`。
2. **已实名但未提交开通申请**：引导商户进入产品开通页填写申请并提交。
3. **已提交申请，审核中**：提示等待审核；等待期间继续推进技术集成、沙箱联调和证书获取。
4. **审核通过但未签约**：主动提醒点击「去签约」，完成合同在线确认与签署。
5. **产品已开通**：提醒商户查看二级商户号、查收 appId/agentId 邮件，并进入证书密钥步骤生成或获取 SM3 密钥。

## 标准话术

服务端代码集成已完成。接下来我会继续帮你做沙箱联调，同时建议你同步推进产品开通，避免后面等审核或签约时空转。

请负责商户入驻、商务合作、财务结算或管理员账号的同事进入 AI付产品开通页：
https://aipay.jdpay.com/process?productId=ai_pay&activeProcessStep=PRODUCT_OPEN

如果页面提示尚未实名，请先点击「去实名」完成实名认证；也可使用实名认证直达模板 `https://qy-web.jdpay.com/select?source=QYZ&channel=00006&scene=SMRZ&bussCode=REAL_NAME&merchantno={merchantno}&r={callback}`，其中 `merchantno` 和 `callback` 需由页面上下文带入，参数不明确时不要手动拼接。实名通过后再回到产品开通页提交申请。申请提交后，通常需要等待审核，审核通过后还需要点击「去签约」完成合同确认，产品才算开通完成。

你这边可以继续把技术集成和沙箱联调做完；等产品开通完成、证书和生产密钥准备好后，我再继续帮你切换生产配置并做线上验证。

## 产品开通页引导要点

- 入口：AI付官网 → 快速接入 → 选择产品 → 传统接入方式 → 立即接入/继续接入 → 产品开通。
- 直达：`https://aipay.jdpay.com/process?productId=ai_pay&activeProcessStep=PRODUCT_OPEN`
- 申请单常见信息：所属行业、商户简称、APP 名称、APP 应用市场、结算账户、产品服务与协议勾选等；字段以页面实时展示为准。
- 提交申请后关注审核状态；审核通过后完成在线签约。
- 产品开通成功后，可在产品开通页查看二级商户号；appId、agentId 等接入配置通常会通过预留联系人邮箱发送。

## 主动引导规则

完成任何一项任务后，不要只等待商户追问。回复末尾必须补一句“下一步建议”，格式如下：

```text
下一步建议：<根据当前状态给出 1 个最关键动作>。入口：<链接或页面路径>。做完后你可以回来告诉我“已完成<事项>”，我会继续帮你推进<下一阶段>。
```

示例：

```text
下一步建议：请先完成产品开通申请；如果页面提示未实名，就先点「去实名」。入口：https://aipay.jdpay.com/process?productId=ai_pay&activeProcessStep=PRODUCT_OPEN。做完后你可以回来告诉我“已提交产品开通”，我会继续帮你确认证书密钥和上线配置。
```
